# k3s

Ansible for the k3s nodes: a small `base` role for the OS, then the official
[k3s-io/k3s-ansible](https://github.com/k3s-io/k3s-ansible) collection
(`k3s.orchestration`) to install the cluster. The same playbooks run against the
lab VMs from [`terraform/proxmox/k3s-lab`](../../terraform/proxmox/k3s-lab/README.md)
and, later, the bare-metal production nodes, so production gets what was
rehearsed in the lab.

## Layout

- `inventory/lab/` is the lab cluster: `hosts.yml` (gitignored, generated by
  OpenTofu) and tracked `group_vars/k3s_cluster.yml` with the k3s settings.
  Production gets its own `inventory/prod/` later.
- `playbooks/base.yml` runs the `base` role: base packages, `qemu-guest-agent`
  on VMs, unattended security upgrades, SSH keys only.
- `playbooks/site.yml` runs `base.yml`, then `k3s.orchestration.site`.

## Setup

Run from any machine (desktop, laptop, container). Alternatively, skip this setup and run `homelab-box` from the
[homelab toolbox](../../homelab-toolbox/README.md), which has Ansible installed. Otherwise use a virtualenv so every
machine gets the same tools:

```bash
cd ansible/k3s
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
ansible-galaxy collection install -r requirements.yml
```

Create the inventory from OpenTofu (or copy `hosts.example.yml` and edit it):

```bash
cd ../../terraform/proxmox/k3s-lab
tofu output -raw ansible_inventory > ../../../ansible/k3s/inventory/lab/hosts.yml
```

## Usage

```bash
cd ansible/k3s
ansible k3s_cluster -m ping
ansible-playbook playbooks/site.yml
kubectl --context k3s-lab get nodes -o wide
```

The collection merges the cluster's kubeconfig into `~/.kube/config` as the
`k3s-lab` context. `ansible.cfg` defaults to the lab inventory; production will
always need an explicit `-i inventory/prod/hosts.yml`.

## Configuration

`inventory/lab/group_vars/k3s_cluster.yml`:

- `ansible_user`: the cloud-init user (`debian`), with passwordless sudo.
- `k3s_version`: pinned k3s release; use the same one in production.
- `api_endpoint`: the first server's address.
- `cluster_context`: kubeconfig context name.
- `extra_server_args`: `--cluster-init` (embedded etcd, so servers can join
  later) and `--disable servicelb` (MetalLB replaces it).
- `token`: omitted, so the first server generates one.
- `lab_domain`: placeholder for the wildcard cert in a later step.

## Troubleshooting

- `REMOTE HOST IDENTIFICATION HAS CHANGED` after a rebuild: run
  `ssh-keygen -R <ip>` for each node.
- Uninstall k3s from all nodes: `ansible-playbook k3s.orchestration.reset`.
