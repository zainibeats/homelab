# Monitoring (OCI)

Prometheus, Grafana, Loki, Alloy, node-exporter and cAdvisor for the OCI host. Grafana sits behind NetBird's Traefik and is reachable only by NetBird peers. The home stack is in [monitoring-home](../monitoring-home/README.md).

| Service | Purpose |
|---------|---------|
| `prometheus` | Metrics, 30 days capped at 5 GB |
| `node-exporter` | Host metrics. Uses the host network, bound to `10.110.9.1:9100` (the `br-monitoring` gateway) |
| `cadvisor` | Per-container CPU, memory, network and disk |
| `loki` | Logs, 7 days |
| `alloy` | Ships container logs (Docker API) and the host journal to Loki |
| `grafana` | `https://GRAFANA_HOST`, with provisioned datasources and dashboards |

**Runs on:** Oracle (OCI)

## Prerequisites

- **Traefik:** [netbird-server](../../networking/netbird-server/README.md) with the `letsencrypt-dns` resolver, and Traefik on `services` at `10.110.2.20`.
- **DNS:** a Cloudflare A record for `GRAFANA_HOST` pointing to `10.110.2.20`, DNS only.
- **ufw:** Docker bypasses ufw for published ports but not for container-to-host traffic, so Prometheus needs a rule to reach node-exporter:
  ```sh
  sudo ufw allow in on br-monitoring to 10.110.9.1 port 9100 proto tcp comment 'prometheus to node-exporter'
  ```

## Setup

1. Copy `.env.example` to `.env` and set `GRAFANA_HOST`.
2. Create the Grafana admin password file. It's git-ignored and must be readable by Grafana's uid 472:
   ```sh
   read -rsp 'Grafana admin password: ' P && printf '%s' "$P" > grafana-admin-password && unset P
   sudo chown 472:472 grafana-admin-password && sudo chmod 400 grafana-admin-password
   ```
   It only applies on first start. After that, change the password in Grafana.
3. `docker compose up -d`, then log in as `admin`.

Config files are bind-mounted, so after editing one, run `docker compose restart <service>`. For Prometheus, `docker compose kill -s HUP prometheus` also works.

Dashboards are files under `grafana/dashboards/` and can't be edited in the UI. The `OCI` ones are generated by `grafana/generate-dashboards.py`. `Community/node-exporter-full.json` is [Node Exporter Full](https://grafana.com/grafana/dashboards/1860).

## Configuration

- `GRAFANA_HOST` - Grafana hostname (e.g. `grafana.domain.tld`).
- `TRAEFIK_NETWORK` - Docker network of the existing NetBird Traefik (`netbird_netbird`).
- `TRAEFIK_ENTRYPOINT` - Traefik entrypoint (`websecure`).
- `TRAEFIK_CERTRESOLVER` - Certificate resolver (`letsencrypt-dns`, for the private-IP hostname).
- `ALLOWED_RANGES` - Source ranges allowed to reach Grafana: NetBird peers (`100.64.0.0/10`) and the routed `services` network (`10.110.2.0/24`).

Service configs: `prometheus/prometheus.yml`, `loki/config.yaml`, `alloy/config.alloy`, `grafana/provisioning/`.

## Routing & Ports

- `https://GRAFANA_HOST` - Grafana through NetBird's Traefik, limited to `ALLOWED_RANGES`.
- No published ports.
- Everything shares the `monitoring` network (`10.110.9.0/24`, bridge `br-monitoring`). Only Grafana also joins Traefik's network (`TRAEFIK_NETWORK`).

## Data & Backups

- `prometheus-data`, `loki-data`, `alloy-data`, `grafana-data` volumes - Metrics, logs, Alloy state, and the Grafana database.
- `grafana-admin-password` - Initial admin password file (gitignored).
- Everything else (configs, dashboards) is in git.

## Troubleshooting

Images track `:latest` and Watchtower updates them. If an update breaks something, pin that service to the last good tag and opt it out of Watchtower:

```yaml
    image: grafana/grafana:13.2.3
    labels:
      - com.centurylinklabs.watchtower.enable=false
```

If Prometheus shows node-exporter as down, check the ufw rule from Prerequisites.
